# QQBot 修仙插件 1.0.0

适用 QQBot V0.0.14 及配套 SDK。采用 C# DLL 入口和完整 Python 游戏引擎，原有16业务模块、128个匹配器、14项定时注册全部保留。它不是纯 C# 改写；引擎独立进程会增加资源消耗，实际 CPU/内存和响应时间由用户实测。插件生命周期由 QQBot 管理，不需要单独启动 NoneBot 窗口或配置 NapCat 密钥。

## 安装与使用

完整 V0.0.14 包已内置插件。独立插件 ZIP 同时包含配套框架，使用桌面“插件与群→选择 ZIP”预览并安装。停止 Host 后提交安装，保留现有插件数据。不能只复制 DLL 到 V0.0.13。

启动机器人后，在已开启修仙插件的 QQ 群发送 `/修仙`。首次自动复制缺失的离线资源，启动解释器并核对注册数量；成功后显示游戏菜单。也可使用 `/修仙 开始`、`/修仙 签到`、`/修仙 属性`、`/修仙 状态`。原版完整指令与别名继续可用；`@机器人 突破` 或 `/突破` 均进入原游戏规则。原游戏以群聊为入口，私聊仅给出使用说明和引擎状态。

首次需在游戏中按上游流程“启用修仙功能”，框架群开关与游戏内启用配置同时生效。真实管理员取自 Host 的 AdminUserIds，群管理员按 QQ 查询确认，不从消息伪造。跨群角色和经济世界沿用原版共享设定；框架群开关控制参与和回复，不把原版世界改成互不相通的独立存档。

## 数据与资源

插件目录下 engine 是固定源码和种子资产，runtime/win-x64 是固定解释器和36个离线 wheel 的展开依赖。真正运行数据位于插件 data 目录，其下 data/xiuxian 包含数据库、配置、头像缓存与 runtime/<模块> JSON。升级、卸载与回退必须整体保留插件 data，不能直接用 engine/data 覆盖。

种子复制只补缺失文件，已有存档不覆盖。源码目录内的可变 JSON 已迁到持久数据目录。原版经济结算部分仍跨数据库和 JSON 多步更新；桥串行消息与定时任务降低交错，但不保证进程崩溃时所有玩法原子提交。发生超时或断线后不会自动重放指令，先查看角色/背包再决定下一步。

## 性能与通信边界

- 普通群聊只做 C# 字符串/固定正则路由；未匹配不启动或调用 Python。
- 游戏队列最多64条；满队列明确提示未执行，不静默丢弃已接受的请求。
- 消息与定时任务在引擎中串行执行。OneBot动作最多8个等待，父通道串行传输；每次实时检查全局与群开关。
- 标准输入输出 JSONL 单帧上限8MiB，图片上限4MiB，动作回执2MiB。无需额外 HTTP/WS 监听。
- 首次启动60秒预算，单次指令120秒预算；超时无自动重发。关闭先请求退出，超过有界等待才回收本插件进程；Windows专有Job处理Host意外退出。
- 只开放原插件所需发送/转发及身份查询动作，不开放禁言、撤回或任意 OneBot 接口。网络凭据由 Host 持有。

## 构建与服务器

从完整 QQBot 源码根执行 dotnet build QQBotFramework.sln -c Release。单独构建此 Fork 时传入 `dotnet build qqbot/plugin/QQBot.Plugins.Xiuxian.csproj -c Release -p:QQBotRoot=D:\QQBot`。依赖锁在 qqbot/requirements.lock，仅包含固定 Windows CPython3.13 wheel 与哈希。

Windows发行带解释器。Linux服务器需自行安装兼容Python、为该服务器平台重新锁定依赖，将 QQBOT_XIUXIAN_PYTHON 指向独立解释器；Windows wheel 不可用于Linux。保持服务器时区与游戏每日规则一致（原日期逻辑使用本地时间，调度器为Asia/Shanghai）。不要运行原上游的自动依赖脚本或把另一框架直接连到同一存档。

## 验证

本次只执行编译、文件/语法/许可证与包校验，没有启动引擎、QQBot、NoneBot、NapCat，未执行API、单元测试、游戏功能或性能测试。用户人工验收入口为 QQBot docs/XIUXIAN.md；每项记录版本、群范围、指令、结果和异常日志。源码审计为 qqbot/audit/REVIEW.md，原资产与依赖来源见 SOURCE-NOTICES.md。
